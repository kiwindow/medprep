## 4. スライド 20 枚 ―― 高さを目分量で置かない

既存教材（`HowToSetUpPC.pptx`）から配色と座標を採った。
大見出し 26pt / 中見出し 17〜18pt / 本文 14〜15pt / eyebrow 14pt / 注記 13pt、**すべて Bold**。

最初は箱の高さを目で決めた。結果、**20 枚のうち 12 枚で本文が箱からはみ出した。**
PowerPoint の文字は箱で切り取られないので、**ファイルとしては壊れておらず、
描いて見るまで分からない。**

`auto_h()` / `code_h()` が本文の量から高さを計算し、`card()` / `code()` /
`callout()` / `table()` が**次を置く位置（下端）を返す**ようにした。
折り返しの見積りには **1 行ぶんの余裕**（`cpl * 0.92`）を入れてある。
Yu Gothic と代替フォントでは折り返し位置が変わるためである。

検算も自動化した。pptx を読み直して
「塗りのある図形の下端が 7.06 インチを超えていないか」を数える。
Phase 10 で HTML をブラウザに描いて確かめたのと同じ考え方である。
**気づけない壊れ方は機械に見張らせる。**

### `**強調**` は色にする

規約で全文字が Bold なので、太さでは強調を表せない。
`**…**` の範囲だけ色を変える（明るい地では青、濃い地では水色）。
markdown をそのまま書くと `**` が画面に出る。最初はそうなっていた。

## 5. 通して実行して見つかった package 側の欠陥 3 つ

いずれも**ノートブックを最後まで走らせなければ出てこなかった**。

### 5-1. `SurvivalFrame` が共変量を持っていなかった

`autoprep` が返す `rep.survival` が ID と (duration, event) だけで、
**Cox に掛けられなかった。** 利用者が元データと結合し直すことになり、
そこで症例を取り違える。schema の特徴量（日付列を除く）を必ず持たせた。

### 5-2. `columns` を Table 1 にも渡していた

`autoprep(columns=...)` は「モデルに入れる特徴量」である。
これを `table_one` にも回していたため、日付や自由記載まで表に並び、
**Table 1 が 2,221 行**になった。意味の違う 2 つを 1 つの引数で兼ねてはならない。
`table1_columns` を分けた。

### 5-3. `table_one` が水準の多い列を 1 行ずつ展開していた

上の結果、自由記載の列が 600 水準ぶんの行になった。渡し方の誤りではあるが、
**そのまま出すほうが間違っている。** `max_levels`（既定 20）を超えたら 1 行にまとめ、
「何水準あったか」「なぜ省いたか」を注記に残す。χ² も意味を持たない。
