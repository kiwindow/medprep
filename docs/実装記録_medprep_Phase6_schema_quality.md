## 2. schema — 「この列は何か」を決め、理由を残す

役割は 15 種：
`id / outcome / time / event / group / datetime / numeric / binary / ordinal /
nominal / high_cardinality / text / constant / duplicate_of / unknown`

```python
sch = mp.Schema.infer(df, id_col="仮名ID", group="施設",
                      survival_dates=("観察開始年月日", "event発生年月日", "観察打ち切り年月日"))
sch.to_yaml("schema.yaml")     # 人が直して再実行できる
sch.diff(edited)               # 手で直した箇所が表で出る
```

**`reason` の無い判断を作らない。** これがこのモジュールの存在理由である。
医学研究では「なぜこの列を落としたのか」を後から説明できることが成果物の価値を決める。
論文の Methods に「前処理は medprep、設定は補足資料の schema.yaml のとおり」と
書ける状態を保つ。

### 判定の順序に意味がある箇所

1. **日付の判定は、ユニーク率による ID 判定より前に行う。**
   逆にすると、ほぼ全行で異なる観察開始日が識別子として落とされる。
2. **ユニーク率だけで識別子と断定しない。**
   備考のような自由記載もユニーク率 1.00 になる。識別子か自由記載かは
   ユニーク率からは決まらないので、`high_cardinality` として外すにとどめ、
   「識別子ではないか」の問いかけは audit が行う。
3. **数値列は列名の裏づけが無ければ順序尺度とみなさない。**
   施設コード {1,2,3,4} は ECOG {0,1,2,3,4} の部分集合になってしまう。
4. **重複列の検出は型をまたぐ。**
   施設（文字列）と施設コード（整数）は完全に対応するのに、
   数値どうし・カテゴリどうしだけを見ていると気づけない。
   水準が 50 以下の列は dtype を問わず Cramér's V（バイアス補正つき）で比べる。

### 往復

`to_yaml` → `from_yaml` で差分 0 を回帰テストで固定した。
ここが崩れると schema.yaml を配る意味が無くなる。

## 3. quality — 「このまま解析してよいか」を問う

**audit は直さない。報告する。** 自動修正は「気づかないうちに直っていた」を生む。
所見（`Finding`）には必ず `action`（どうすればよいか）が付く。
これも回帰テストで固定した（`action` が空の Finding を作れない）。

重大度は 3 段階。`error` は「このまま解析すると誤った結論になる」ものに限る。
error を乱発すると読まれなくなる。

### 15 種の検査

| 区分 | 見ているもの |
|---|---|
| 重複 | 全列一致の行／**同一 ID の複数行**／ID 以外が一致する行 |
| 識別子 | ユニーク率の高い文字列列／全例で異なる整数列（連番の疑い） |
| 重複列 | schema が落とした列の報告／\|r\| 0.95〜0.999 の多重共線性 |
| 日付 | **並びが確定できない列**／未来の日付／1900 年以前／解釈できない値 |
| 生存時間 | イベント日と打ち切り日の両方／どちらも無い／開始日が無い／逆転／0 日／60 年超／イベント数 |
| 目的変数 | 単一クラス／最小クラス 10 例未満／9 倍超の不均衡／欠測（**補完してはならない**） |
| リーク | 目的変数と \|r\|≥0.99 または Cramér's V≥0.99 の説明変数 |
| 群 | 10 例未満の水準／20 を超える水準数 |
| 欠測 | 列の欠測率／行の欠測率／**欠測が群に偏っていないか**（χ²、p<0.001） |
| 表記ゆれ | 正規化すると同じになる値が別々の水準として入っている |
| 検算 | **白血球分画の合計**／桿状核球＋分葉核球 ≒ 好中球 |
| 項目間 | **Fe>TIBC（TSAT>100%）**／SBP≤DBP／Payne 式と合わない補正Ca／あり得ない BMI |
| 採血時点 | 時点が不詳の項目／前後の片方しか無い項目 |
| 前後の向き | **透析前後の取り違え** |
| 測定法 | **測定法変更を挟んだ分布の段差** |

### 中核となる 2 つ

**透析前後の取り違え。**
BUN・Cr・K・P・UA・β2MG・体重は透析で下がる。Hb・Ht・TP・Alb は血液濃縮で上がる。
向きが逆の症例が過半数なら、それは病態ではなく列の取り違えである。
取り違えたまま spKt/V を計算すると透析量が過大に評価され、
**しかもどの値も単独では正常範囲に見える**。
1 割から半分なら個別の入力ミスとして warn にとどめる。

**測定法変更の段差（`method_change_steps`）。**
ALP は 2020 年 4 月に JSCC 法から IFCC 法へ切り替わり、同じ患者の同じ状態で
値がおよそ 1/3 になった。段差を病態として解析すると
「2020 年以降の症例は骨代謝が良い」という存在しない所見が出る。
辞書の `measurement_changes` の変更日で前後に分け、中央値比と
Mann-Whitney 検定で段差を判定する。合成データでの検出結果：

```
[✗] 測定法: 'アルカリフォスファターゼ(ALP)' は 2020-04-01（JSCC 法 → IFCC 法）の
    前後で中央値が 246 → 91（0.37 倍、p=4.2e-33、前 539 例 / 後 61 例）と段差になっている
      → 期間を共変量に入れるか、期間で層別すること
        既知の影響: 値がおよそ 1/3 になる（例: 240 U/L → 80 U/L）
```

Alb の BCG→BCP 改良法のように変更日が施設ごとに違うものは、
日付が特定できない旨と「測定法を記録すること」を info として出す。
**日付列を渡さなかった場合は「調べられなかった」ことを明示する**
（`rep.skipped`）。黙って検査を飛ばさない。

## 4. 新しいテストが見つけた欠陥（schema.py の 2 件）

いずれも**実データで確実に起きるもの**で、例外を出さずに通る種類の欠陥だった。

### 数値判定が緩すぎた

「数字以外の文字を全部落として数値化できるか」で判定していた。
このため `特記なし_12`（備考欄の自由記載）が `12` として**数値列にされていた**。

**数値は先頭にあること**、後ろに続くのは数字を含まない短い単位であることを
要求するようにした。

```
受け入れる: '12' '-0.5' '1,200' '<0.1' '3.2 mg/dL' '5回' '1.2e3'
受け入れない: '特記なし_12' 'P0001' 'A院' '2013/3/3'
```

### ユニーク率 > 0.90 の列を無条件に落としていた

年齢・Cr・BNP のような連続値は、症例数が少なければユニーク率 1.00 になる。
60 例のデータで年齢が 60 通りなら、それは「ほぼ全行で異なる列」である。
**いちばん大事な説明変数から先に消えていた。**

この規則は文字列の識別子を捕まえるためのものなので、**数値として読める列には
適用しない**ことにした。数値の識別子は列名（`_ID_NAME`）か `id_col` の指定で捕まえる。
それでも漏れる「全例で異なる整数で、辞書のどの項目にも当たらない列」は
audit が「連番の識別子ではないか」と問いかける。

## 5. 合成データの欠陥（docstring と実物が食い違っていた）

`examples/make_synthetic.py` の docstring は
「11. 2020年4月のALP測定法変更による段差」を仕込んだと書いていたが、
**実際には入っていなかった。**
登録期間が 2013-01-01 から 1600 日（= 2017 年 5 月まで）だったため、
`start.year < 2020` が全例で真になり、ALP は全例が JSCC 期の分布だった。

修正：

* 登録期間を 2011-01-01 から 3300 日（= 2020 年 1 月まで）に広げた。
  観察期間は最長 2200 日なので、観察終了は最も遅くても 2026 年初めで、
  未来日付は生じない（audit の未来日付検査に引っかからない）。
* **`検体採取日` の列を追加した。** 検査値は観察期間中のある 1 回の採血パネルから
  取ったものとし、ALP はこの日で前後に分ける。結果、2020-04 以降が 61 例となり、
  中央値 246 → 91 の段差が実際に検出できるようになった。
* 文字列の汚れを入れる列を先に `object` にした
  （float 列への文字列代入は pandas 3 でエラーになる）。

## 6. モジュール名を audit ではなく quality にした理由

`audit.py` にすると、`import medprep.audit` がパッケージ属性 `medprep.audit`
（関数）をモジュールで**上書きする**。その後 `mp.audit(df)` が突然呼べなくなる。
教材のコードで名前がふたつの意味を持つ状態を作らない。
モジュールは `quality`、公開する関数は `audit()` とした。

## 7. 通し検証（`run_e2e.py`）

```
1) データ読み込み

3) データ品質監査（audit）          ← 追加
4) 辞書駆動の掃除

6) 4列の日付 → (duration, event)
7) Table 1
8) Kaplan-Meier + log-rank

```
