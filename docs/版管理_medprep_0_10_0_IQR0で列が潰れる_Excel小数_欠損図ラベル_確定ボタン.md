## 1. ★いちばん重い不具合：外れ値処理が列を丸ごと潰していた★

### 症状

`前処理済み_train.xlsx` の `透析時間(hr)` が **全例きっかり 0**（標準偏差 0）。

```
       透析時間(hr)
count     428.0
mean        0.0
std         0.0          ← ★列が死んでいる★
```

### 原因

`iqr_limits()` が **IQR = 0 を弾いていなかった。**

```python
q1, q3 = v.quantile(0.25), v.quantile(0.75)
iqr = q3 - q1
return q1 - fold * iqr, q3 + fold * iqr     # iqr = 0 なら上下限が同じ値になる
```

値が数種類しかない列では Q1 = Q3 になる。**透析時間は 4.0 時間が 6 割**を占めるので、
まさにこれに当たっていた。上下限が `(4.0, 4.0)` になり、winsorize が全例を 4.0 に
丸める。分散 0 の列になり、StandardScaler を通ると全例 0 になる。

**例外は出ない。** 図も表も正常に見えたまま、その変数だけがモデルから消える。

`mad_limits()` は「MAD が 0 になる列がある（検出限界未満が多い CRP）」として
同じ事故を防いでいた。**IQR 法だけ抜けていた。**

### 直し方

1. `iqr_limits()` は IQR = 0 のとき閾値を作らない（`±inf`）。
2. **`Preprocessor.fit()` が、出来上がった行列に値が 1 つしかない列が無いか見張る。**
   あれば `record.warnings` に出す。別の経路で同じことが起きても気づける。

> 教訓: **黙って壊れる経路には、必ず後段に見張りを置く。**
> 直した箇所だけを直しても、同じ形の事故は別の入口から入ってくる。

### 合成データも直した

透析時間を 3.5 / 4.0 / 4.5 / 5.0 の 4 値から、**15 分刻み・中央値 4.0 時間・
3.0〜5.5 時間**に広げた。実務のばらつきに合わせ、かつ IQR が 0 にならないようにする。

```
内訳: 3.00:6  3.25:23  3.50:57  3.75:119  4.00:145  4.25:127
      4.50:76  4.75:36  5.00:8   5.25:2   5.50:1
```

## 2. Excel で小数が見えなくなっていた

書式を指定せずに書いていたため、表示環境によっては **CRP の 0.05 が「0」**に見えた。

**列ごとに、いちばん小さい非ゼロの値が 2 桁の有効数字で読める桁数**を当てる。

| 列 | いちばん小さい非ゼロ | 書式 |
|---|---|---|
| C反応性蛋白(CRP)定量 | 0.01 | `0.000` |
| アルブミン(Alb) | 2.1 | `0.0` |
| 年齢 | 26 | `0`（整数） |
| duration | 0.0027 | `0.000` |

桁数を 1 に固定すると 0.05 が「0.1」、0.01 が「0.0」になる。**固定値ではだめである。**
列幅も見出しの長さに合わせて広げた。

## 3. 検出限界の印の列名を日本語にした

`C反応性蛋白(CRP)定量__censored_low` は、Excel で列名が切れると **「CRP」に見える。**
中身はほぼ全部 0 なので、**「CRP が全部 0 になっている」と読まれる。**

`検出限界未満_C反応性蛋白(CRP)定量` に変えた（`__censored_high` → `検出限界超_`）。
先頭に用途が書いてあれば、値の列と見間違えようがない。

## 4. 欠損の地図の列名が重なって読めなかった

40 列の日本語の列名を、既定の大きさ（16pt）・45 度で描くと、**文字どうしが重なって
1 文字も読めない。** 図としては描けているので例外は出ない。

- 列数から**図の幅**を決める（1 列 0.34 インチ、最大 26 インチ）
- **1 列あたりの幅に収まる字の大きさ**を計算して当てる
  （日本語は全角なので、字の幅 ≒ 大きさ(pt) とみなす）
- 列が多い・名前が長いときは**縦書き（90 度）**にする。
  横に要る幅が**字 1 つぶん**で済むので、重ねようがない

`viz.fit_tick_labels()` として切り出してあるので、他の図にも使える。

## 5. 演習NB Ver2_0 ―― ［確定する］ボタン

列を選ぶ画面に ［確定する］ を足した（［すべて指定しない（skip）］の左）。

- **押さなくても同じである。** 選んだ時点で反映される（0.9.3 の動き）。
- 押した場合は「◆ 確定した。」と出して、今の設定を表示する。
- **何も操作しなければ、推定した既定の選択がそのまま有効になる**という動きは
  そのまま残してある。**操作が分からなくても計算が進むための保険**である。
