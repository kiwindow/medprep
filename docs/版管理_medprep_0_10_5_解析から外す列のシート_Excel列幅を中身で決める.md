## 2. なぜ「のみ」が要点なのか

列の扱いには**二通り**ある。`rep.removed` の `処置` 列がそれを区別している。

| 処置 | 解析用データに | 説明変数に | 例 |
|---|---|---|---|
| **解析から外した（列を削除）** | **残らない** | 使わない | 仮名ID / 施設コード / 透析開始時刻 / 透析終了時刻 / 備考 |
| 特徴量にしなかった（列は残る） | 残る | 使わない | 日付の列・`duration`・`event`・`_start`・`_end` |

後者は**そのままでは説明変数にならない**が、症例を確かめるのに要るので
ファイルには残す。この二つを一緒に並べると、
**「消えた」と言われた列が手元のファイルにあって人が混乱する。**
だから 3 枚目には**前者だけ**を入れる。

★`掃除済みデータ.xlsx` には全列がそのまま残る。★
あれは人が元の記録と突き合わせるためのものなので、ID も自由記載も抜かない。
消えるのは `解析用データ.xlsx` から先である。

## 3. 変更

### 3.1 `除外の記録.xlsx` が 3 枚組になった

| シート | 中身 |
|---|---|
| まとめ | 何を、いくつ、なぜ減らしたか（列・行・値の集計） |
| 外すのが望ましい症例 | 1 症例 1 行。元の行・ID・理由・関係する日付 |
| **解析から外す列** | **列名・理由・どの段で消えたか** |

合成データ 600 例での実際の中身:

| 列 | 理由 | 段 |
|---|---|---|
| 仮名ID | 人が id_col として指定した | 列の役割の推定（id） |
| 施設コード | '施設' と Cramér's V = 1.0000 ≥ 0.999（実質同じ情報） | 列の役割の推定（duplicate_of） |
| 透析開始時刻 | 水準 30 > 24（= max(20, √n)）。既定では解析に入れない | 列の役割の推定（high_cardinality） |
| 透析終了時刻 | 水準 74 > 24（= max(20, √n)）。既定では解析に入れない | 列の役割の推定（high_cardinality） |
| 備考 | ユニーク率 1.00 > 0.90（ほぼ全行で異なる）。識別子なら id_col で指定すること | 列の役割の推定（high_cardinality） |

### 3.2 API

```python
mp.removed_columns(rep)      # Excel の 3 枚目と同じ表
```

### 3.3 処置の文字列を定数にした

```python
COL_DROPPED = "解析から外した（列を削除）"
COL_UNUSED  = "特徴量にしなかった（列は残る）"
```

★表に書く文字と、抽出に使う文字を二か所に書いてはいけない。★
片方だけ直したときに、抽出が黙って空になる。

## 4. ついでに見つかった不具合 ―― Excel の文字が切れていた

3 枚目を LibreOffice で PDF に起こして**目で見た**ところ、
`理由` の文が途中で切れていた。`まとめ` の `処置` も
「解析から外した（列を削除）」が**「解析から外」**で切れていた。

原因は `_fmt_sheet` が列幅を**見出しの長さだけ**から決めていたこと。

```python
width = min(28, max(10, len(head) + 2))   # ← 見出ししか見ていない
```

「理由」は見出しが 2 文字で中身が 40 文字である。
隣のセルが空でなければ Excel は文字をはみ出させないので、
**切れた文字は画面から消える。** 理由が読めない一覧に値打ちはない。

中身の最大幅から決めるように直した。★日本語は 2 桁分として数える。★
`len()` で測ると日本語の列だけが必ず半分の幅になる。
上限は 70 桁（自由記載の 1 行で画面が埋まるのを防ぐため）。

この修正は `除外の記録.xlsx` だけでなく、`_fmt_sheet` を使う
**すべての Excel 出力**に効く。
