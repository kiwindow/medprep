## 2. 原因① ── 合成データが作り直されていなかった（★これが本丸★）

演習NB の［演習用の合成データを使う］はこう書いてあった。

```python
p = os.path.join(DATA_DIR, 'synthetic_dialysis_cohort.xlsx')
if not os.path.exists(p):     # ★ここ★
    mp.demo.save(p)
```

**「無ければ作る」。** つまり、一度作ったら二度と作り直さない。
0.6.0 で透析前後の 2 点（BUN・Cr・K・体重）・身長・透析時間を足したが、
**前に作った 20 列のファイルが残っていたので、実機には一度も出ていなかった。**
User の画面に前後の列が無かったのはこのためである（パッケージは新しかった）。

### 直し方

**押すたびに作り直す。** 合成データは seed 固定なので、作り直しても中身は同じ。
「版が上がったのに古いファイルが残る」という状態が二度と作れない形にする。
作った版（`medprep x.y.z`）と、透析前後を含むことを画面に出す。

> 教訓: **キャッシュは「古いまま正しく動く」ので、失敗が例外にならない。**
> 生成物のキャッシュは、生成側の版に連動させるか、作り直すかのどちらかにする。

## 3. 原因② ── 0/1 化が「モデルに渡す行列」の中だけで効いていた

0.7.0 の `BinaryMapper` は `Preprocessor`（`ColumnTransformer`）の中にある。
効くのは `前処理済み_train.xlsx` / `_test.xlsx` だけで、
`解析用データ.xlsx` は `df_clean[keep]` をそのまま書いていた。

    前処理済み_*.xlsx  →  男性 0/1     ← 0.7.0 で直った
    解析用データ.xlsx  →  性別 男/女   ← 直っていなかった  ★食い違い★

### 直し方

`encode_binary_columns(df, schema)` を追加し、**同じ規則**を素の DataFrame に掛ける。

- 列は**同じ位置で置き換える**（列の並びは変わらない）
- 列名は `binary_output_name()`（性別 → **男性**、あり/なし → 元の列名）
- 対応表に無い値は**勝手に 0 にせず**欠損にし、件数を報告する

`autoprep()` に段を 1 つ足し、`rep.df_use`（解析用データ）と
`rep.encoded`（何を 1 にしたかの表）を返す。
`解析用データ.xlsx` の 2 枚目に「0と1の対応」を入れる。

### ★掃除済みデータには掛けない★

`掃除済みデータ.xlsx` は<u>人が元の記録と突き合わせる</u>ためのものである。
`男/女` が `1/0` になっていたら照合できない。**意図して残す。**
この区別を NB とレポート（新節「1d. 二値の列を 0/1 に直した」）に明記した。

| ファイル | 性別 | 目的 |
|---|---|---|
| 掃除済みデータ.xlsx | 男 / 女 | 人が元の記録と突き合わせる |
| 解析用データ.xlsx | **男性** 1/0 | 自分で解析する |
| 前処理済み_*.xlsx | **男性** 1/0 | モデルに渡す |

## 4. 教材（演習NB Ver1_7）

**演習④「透析前後の 2 点 ―― どちらが『前』かを推測で決めない」を新設。**
（以降の演習番号が 1 つずつ繰り下がる。④Table1→⑤、⑤生存→⑥、⑥モデル→⑦）

演習①には「二値の列を 0/1 に直した」の節を足し、`rep.encoded` と
`rep.df_use` を見せる。
