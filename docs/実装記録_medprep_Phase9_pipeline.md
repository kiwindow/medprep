## 2. 中核：リークを「気をつける」ではなく「できない」にする

中央値補完を分割の前に書いた瞬間にリークが入り、**例外は出ない**。
精度がわずかに良くなるだけなので、誰も気づかない。
だから順序を人の記憶に頼らせず、`Preprocessor` に 3 つの見張りを置いた。

| 状況 | 動作 |
|---|---|
| `fit(test)` | **`LeakageError` で止める**（`split()` が付けた印を見る） |
| `fit(全データ)` | 警告（最も多いリークの形） |
| `transform` する行が fit の行と部分的に重なる | 警告（train と test が混ざっている合図） |

```
>>> mp.Preprocessor(sch).fit(sp.test)
LeakageError: test に fit しようとしている。**これはリークである。**
  前処理の統計量（補完の中央値、スケーラの平均、one-hot のカテゴリ集合、
  winsorize の閾値）は train からしか学習してはならない。
```

`leak_check()` は、通ったことを**表として残せる**ようにしてある。

```
              検査 結果                    内容
   train/test の印 OK train=train、test=test
           行の重なり OK                 重なりなし
       fit に使った行 OK  train の行だけで fit している
目的変数が特徴量に入っていないか OK       目的変数 = 1年以内イベント
 識別子が特徴量に入っていないか OK        識別子 = ['仮名ID']
  同じ患者が両側に出ていないか OK                 重なりなし
```

「統計量が train からしか来ていない」ことは、テストで数値として固定した。
test の平均が train と大きく違うデータを作り、変換後の test の平均が 0 から
離れたままであることを確かめる（0 になっていたら test で fit し直している証拠）。
補完値・winsorize の閾値についても同じ形で固定した。

## 3. 列名を失わない

出力は**列名付き DataFrame**（`set_output("pandas")` ＋
`verbose_feature_names_out=False`）。これを失うと係数プロットも SHAP も
`x0, x1, …` になり、教材として成立しない。

さらに読める名前に直した：

* sklearn の `missingindicator_年齢` → **`欠損あり_年齢`**（`RenameFeatures`）
* one-hot は **`施設=B院`** の形、`infrequent_sklearn` → **`稀な水準`**
* one-hot は既定で基準水準を落とし、`reference_levels()` でどれを基準にしたかを出す
  （**基準が分からなければ係数もオッズ比も読めない**。Cox のダミー化と同じ規約）

通し検証の最後で、ロジスティック回帰の係数がそのまま読める：

```
年齢              0.562
Alb            -0.378
Hb             -0.359
糖尿病=1           0.251
欠損あり_年齢        -0.226
```

**「欠損あり_年齢」が係数を持っている**のが医学データらしいところで、
「測っていないこと自体が情報である」を目で見せられる。

## 4. 分割 — リークはここで始まる

* **同一 ID に重複があれば自動でグループ単位に分ける。**
  行単位で分けると同じ患者の別の測定が両側に入り、モデルは患者を覚えるだけで
  高い精度を出し、新しい患者ではまったく動かない。
  `quality.audit` の「同一 ID の複数行」とここが繋がる。
* 分類は目的変数で、生存時間は**イベントで層化**する
  （層化しないと test のイベントが偶然 0 件になる）。
* `time_order=` で**時間順分割**。過去で学習し未来で検証するのが臨床予測モデルの
  本来の検証であり、無作為分割は必ずこれより楽観的な値を出す。
* train と test の分布を **SMD** で比べ、|SMD| ≥ 0.2 の列を警告する。
  合成データでは施設（SMD 0.228）と iPTH（0.278）が引っかかった。
* グループ数が分割数に足りない場合（3 施設を単位に `test_size=0.25`）は、
  sklearn の分かりにくいエラーになる前に実現可能な分割数に丸め、
  **施設単位の分割は外部妥当性の検証である**と注記する。

## 5. 欠損 — 補完はしない

補完は統計量を学習する処理なので train でしか fit できない。
したがって補完は `pipeline` の中にしか置かない。`missing` は**見て考えるための材料**を出す。

* 列別・症例別・パターン別の欠損
* `mcar_signals()` — 「どの列の欠損がどの列と結びついているか」を総当たりで検定し、
  **名指しする**（Little の MCAR 検定は仮定が強いので採らない）
* `drop_missing_outcome()` — **目的変数は補完してはならない。** 除外数を必ず返す
* 形式C の生存時間の日付列は対象外（空欄が「イベント無し」を意味する）

## 6. 外れ値 — 入力ミスとは別のもの

Hb 0 g/dL は外れ値ではない。**入力ミス**であり、`clean` が先に NaN にしている。
ここに出るのは「生理学的にはあり得るが、この集団の中では極端」な値である。
CRP 28 mg/dL は敗血症の症例であって、**削除してはならない**。

* `NanSafeWinsorizer` — NaN を素通しする sklearn 変換器。
  feature-engine の `Winsorizer` は NaN で停止するため、
  「あり得ない値を NaN に → winsorize → 補完」という順序が組めない。だから自作した。
  **閾値は fit でしか決めない。**
* **MAD が 0 になる列では閾値を作らない。**
  半数以上が同じ値（検出限界未満が多い CRP）で起きる。0 で割ると全例が外れ値になる。
* 外れ値が 5% を超える列は「外れ値」ではなく「歪んだ分布」。
  正規分布なら IQR 法で外れるのは 0.5% ほどである。
* 群ごとの閾値。A 院 10 前後・B 院 100 前後という指標では、
  全体の四分位範囲が**群間の差そのもの**になって閾値が広がりすぎ、群内の外れ値を全部見逃す。
* `drop` は人が明示したときだけ。実行したら「削除した症例の一覧を補足に残すこと」と言う。

## 7. 新しいモジュールが見つけた欠陥（実害あり）

```python
out["補正Ca"] = np.where(alb < 4.0, ca + (4.0 - alb), ca)     # ← 誤り
```

`np.nan < 4.0` は `False` に落ちるため、**Alb が欠測の症例で「補正されていない Ca」が
補正Ca として黙って混ざっていた。** 合成データ 600 例では **49 例**が該当した。
管理目標の達成率（補正Ca 8.4–<9.5）も Cox の係数も、その分だけ静かにずれる。

見つけたのは `missing.mcar_signals()` である。

```
欠損した列 関連する列        検定    統計量   p                      内訳
アルブミン(Alb)  補正Ca  Mann-Whitney  8038.0  <0.001  欠損あり 中央値 8.9 / 欠損なし 9.4
```

「Alb の欠測と補正Ca が関連している」という所見を追ったら式の欠陥に行き着いた。
**欠損の偏りを検査する道具が、派生指標の欠陥を見つけたことになる。**
算出不能として NaN にするよう直し、回帰テストで固定した。

## 8. 分布のずれは train 自身の丸め率と比べる

winsorize の閾値は train で学習するので、train の範囲の外にある test の値は丸められ、
その分の違いが失われる。これは分布がずれている合図である。

ただし「test の丸め率が 1 割」だけでは判定できない。CRP のようにもともと歪んだ列は
**train でも 1 割丸められる**。最初の実装はこれを毎回「分布がずれている」と言っていた。
train 自身の丸め率を fit 時に記録し、それより目立って高いときだけ知らせるよう直した。
比べないと、本当のずれが日常的な警告に埋もれる。
