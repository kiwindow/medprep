## 2. Table 1 / Table 2（`medprep.tables`）

### 2.1 なぜ 2 枚に分けるか

`table_one()` は「全体の記述」と「群間比較」を 1 枚に詰めていた。
**読む側の目的が違うのに 1 枚だと、どちらも読みにくい。** 論文でも普通は分ける。

| | 中身 | p 値 |
|---|---|---|
| **Table 1** | 全症例の背景（N と分布だけ） | ★載せない★ |
| **Table 2** | 群ごと + 群間比較（★0.9.1 で「全体」の列を外した★） | 右端に 1 列 |

`group` の指定が無ければ **Table 1 だけ**を作る。

### 2.2 書式

```
連続変数    平均値 ± 標準偏差 [最小値, 最大値]
離散変数    n (%)
p 値        右端の 1 列だけ
検定手法    ★表の中に書かず、脚注に回す★
```

検定手法を行ごとに書くと表が横に伸びて読めなくなる。しかし
**どの検定を使ったかを書かない表は査読に通らない。** だから脚注に必ず出す。
検定の選択そのものは既存の `compare_groups()` が担う（正規性・群数・期待度数で自動）。

二値の列は **1 側の水準を先**に置く（`性別 — 女 / 男` では主語が分からない）。
`schema` の `value_map` を使うので、`男/女` でも `M/F` でも同じ並びになる。

掃除の過程で付けた内部フラグ（`__censored_low`、`欠損あり_…`）は**人が読む表に出さない**。

### 2.3 日本語版と英語版

`medprep/i18n.py` に対訳表を置いた。

- `NAME_EN` … 辞書項目 86 個の英語名
- `COLUMN_EN` … 辞書に載らない列（属性・派生・日付）
- `TIMING_EN` … 透析前 → Pre-dialysis、透析後 → Post-dialysis
- `LEVEL_EN` … 男 → Male、A院 → Hospital A、あり → Yes
- `UNIT_EN` … 歳 → years、月 → months、時間 → hours
- `TEST_EN` … 検定名（脚注用）

★対訳が無いものは訳さずそのまま残す。★ 勝手にローマ字にしない。
`i18n.missing_english()` で「訳せなかった列」を数えられる。

**同じ数値から 2 版を作る。** 人が訳し直すと、そこで誤訳と写し間違いが入る。
テストで「日本語版と英語版の数値セルが完全に一致すること」を確かめている。

### 2.4 書き出し

| 出力 | 中身 |
|---|---|
| `table/Table1_2.xlsx` | **sheet1 = 日本語 / sheet2 = 英語** |
| `table/Table1_2.docx` | **ページを分けて日本語 → 英語**。中詰め・三本罫線 |
| `GTSummary.to_html()` | notebook に出すと**選んでコピーして Word に貼れる** |

Word は、群が多くて横に伸びる表（列数 > 4）だけ**自動で横置きページ**にする。
縦置きのままだとセルの中で `57.3 ± 10.6 [30.0, 88.3]` が 3 行に折り返して読めない。
見出し行はページをまたいでも繰り返す。数値セルは折り返さない（` ` で固定）。

## 3. 透析の派生指標

揃っている列の組についてだけ作る（`clean.derive_dialysis`）。

| 作る列 | 要る列 | 式 |
|---|---|---|
| `除水量(kg)` | 透析前体重・透析後体重 | 前 − 後 |
| `URR(%)` | 透析前BUN・透析後BUN | (前 − 後) / 前 × 100 |
| `透析時間(hr)` | 透析開始時刻・透析終了時刻 | 終了 − 開始（日またぎは +24h） |
| `spKt/V` | 前後BUN・除水量・透析後体重・透析時間 | Daugirdas 第2世代式 |
| `TSAT(%)` | Fe・TIBC | Fe / TIBC × 100 |
| `iCa(mg/dL)` | Ca・Alb | Ca + (4 − Alb) |

**揃っていない組からは作らない。** 片方だけで推測した値を入れると、
それが計算値なのか実測値なのか、あとから誰にも分からなくなる。
既に同じ名前の列があるときも作らない（人が入れた値を上書きしない）。

### 3.1 ★spKt/V の UF は L である★

```
spKt/V = −ln(R − 0.008t) + (4 − 3.5R)·UF/W
  R = 透析後BUN / 透析前BUN
  t = 透析時間 [hr]
  UF = 除水量 [L]     ← ★依頼文では ml だったが L が正しい★
  W = 透析後体重 [kg]
```

Daugirdas 第2世代式の UF は **L**（W が kg なので無次元になる）。
ml を入れると第2項が 1000 倍になり、Kt/V が 2000 を超える。
水 1 L = 1 kg なので、`除水量(kg)` の数値をそのまま L として使ってよい。
**実装は L。脚注にも「UF は L」と明記した。**

### 3.2 ★iCa の式を無条件にした★（→ **0.9.1 で条件つきに戻した**）

依頼は `iCa = 透析前Ca + (4 − 透析前Alb)` である。
0.8.0 までは「Alb < 4.0 のときだけ補正する」という日本の運用に合わせていた。

**Alb ≥ 4 の症例で値が変わる。** 例: Ca 9.0 / Alb 4.2 → 9.0 だったものが 8.8。
`audit` の検算（Payne 式との照合）も同じ式に合わせた。
★ただし 0.9.1 で「Alb < 4.0 のときだけ補正する」Payne 式に戻している。★
列名は `補正Ca` → `iCa(mg/dL)`、`補正Ca×P` → `iCa×P`。
古い名前は辞書の別名に残してあるので、読み込み側は従来どおり動く。

### 3.3 時刻の読み方

実務の時刻列は `9:30`・`09:30`・`9時30分`・全角コロン・Excel のシリアル小数
（0.395833… = 9:30）が平気で混ざる。全部読む。**読めないものを 0 にはしない**
（NaN にして件数を報告する）。日をまたぐ夜間透析は +24h とする。

## 5. 列をクリックで選ぶ（演習NB Ver1_8）

★環境変数に書いてあればそれが最優先。★ 空のときだけ選択画面が出る。

```
GROUP   = ''      # '' なら 4) で選ぶ
SURVIVAL_DATES = ()
OUTCOME = None
TASK    = None
```

4) でデータを読み込んだ直後に、

1. 列名を**すべて番号つきで表示**する
2. 選ぶ対象ごとにドロップダウンを出す（列名が全部入っている）
3. 手がかりの語（施設・観察開始・打ち切り…）から**初期値を提案**する
4. `OUTCOME` を選ぶと `TASK`（回帰/分類）を提案する。★決めつけではなく提案★
5. 「この指定で進む」「指定しない（skip）」の 2 ボタン

自動実行（`LOCAL_DATA_PATH` を書いたとき・D&Dアプリ）は**待たずに**推定値を当てはめる。
